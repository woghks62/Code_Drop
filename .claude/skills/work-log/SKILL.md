# 작업일지 작성 스킬

> 이 스킬은 **절차와 멘트 규격만** 정의한다.
>
> 규칙의 내용은 이 문서에 적지 않고, 각 단계에서 지정한 원본 문서의 섹션을 읽고 따른다. (`CLAUDE.md`의 `규칙 문서 관리` - 단일출처 유지)

## 절차

### 1. 기록 확인

- `Work Log Rule.md`의 `8. 기타 - 파일 위치`를 읽고, 금일 날짜의 작업일지 파일이 이미 있는지 확인한다.
- 작성자는 Git 사용자명(`git config user.name`)으로 한다.
- 금일 커밋(`git log`)과 PR 목록을 확인한다. (`Work Log Rule.md`의 `6. 금일 커밋 / PR`)
    - Git 기록은 읽기만 하며, 기록을 생성·변경하는 Git 명령은 실행하지 않는다.
- 확인한 기록과 대화 내용을 바탕으로 `금일 작업 내용`의 초안 항목을 정리한다.

### 2. 정보 수집

- 아래 **정보 요청 멘트**로 사용자에게 한 번에 질문한다.
- `막히거나 헤매었던 부분`은 `Work Log Rule.md`의 `3. 막히거나 헤매었던 부분`에 적힌 질문 절차를 따른다.
- `개인 회고록`은 `Work Log Rule.md`의 `7. 개인 회고록`을 따르며, 사용자가 답하지 않으면 비워둔다.
- 그 외 필요한 정보가 부족하면 질문하고, 임의로 채우지 않는다.

### 3. 초안 작성

- `Work Log Template.md`의 양식을 기반으로 작성한다.
- 각 섹션은 `Work Log Rule.md`의 해당 섹션(`1. 날짜 / 작성자` ~ `7. 개인 회고록`)과 `8. 기타 - 작성 기준`을 따른다.

### 4. 승인 요청

- 아래 **승인 요청 멘트**로 초안을 요약해 사용자의 승인을 받는다.
- 사용자가 전문을 요청하면 초안 전체를 보여준다.
- 금일 파일이 이미 있으면, 추가·수정되는 부분을 변경 전/후로 보여준다.
- 수정 요청 시 `3. 초안 작성`으로 돌아간다.

### 5. 저장

- 승인 후 `Work Log Rule.md`의 `8. 기타 - 파일 위치`에 따라 저장한다.
- 저장한 파일 경로를 보고한다.

## 멘트 규격

> 아래 형식을 그대로 사용하며, 각 항목은 한 줄로 간결하게 적는다.

### 정보 요청 멘트

```
📋 작업일지 정보 확인
- 금일 작업 (기록 기준) : [항목 1], [항목 2] - 빠지거나 다른 내용이 있나요?
- 금일 커밋 / PR : 커밋 n개 / PR n개
1. 오늘 막히거나 헤매었던 부분이 있었나요?
2. 남겨둔 일과 내일 할 일은 무엇인가요?
3. 회고록에 남길 내용이 있나요? (없으면 비워둡니다)
```

### 승인 요청 멘트

```
📝 작업일지 저장 승인 요청
- 파일 : Docs/WorkLog/YYYY-MM-DD.md (새 파일 / 기존 파일 수정)
- 핵심 작업 : [한 줄 요약]
- 금일 작업 : n개 항목
- 막힌 부분 : n개 / 없음
- 회고록 : 작성 / 비워둠
전문이 필요하면 요청해주세요. 저장할까요?
```
