## 절차

### 1. 권유 판단

- `WorkflowRules.md`의 `5. PR` 섹션을 읽는다.
- 사용자가 Push 완료를 언급하면, 아래 **권유 멘트**로 PR 작성을 권유한다.
- 사용자가 직접 PR 등록을 요청한 경우 이 단계를 생략한다.

### 2. 정보 수집

- 현재 브랜치와 PR 대상 브랜치를 확인한다.
    - 대상 브랜치는 `Develop`을 기본으로 한다. 사용자가 다른 브랜치를 지정하면 그 브랜치로 한다.
- 대상 브랜치와의 커밋 목록, 변경 파일 목록을 확인한다.
- 관련 Issue를 사용자에게 확인하고, Issue가 있으면 본문의 `완료조건 (DoD)`을 가져온다.
    - 관련 Issue 처리는 `Github PR Rule.md`의 `2. 관련 Issue`를 따른다.
- 완료조건 항목별 검증 결과를 사용자에게 질문한다. (`Github PR Rule.md`의 `5. 검증 결과`)
- 남은 작업, 리뷰 요청 사항이 있는지 질문한다.
- 필요한 정보가 부족하면 질문하고, 임의로 채우지 않는다.

### 3. 초안 작성

- `PR Template.md`의 양식을 기반으로 작성한다.
- 각 섹션은 `Github PR Rule.md`의 해당 섹션(`1. Title` ~ `7. 리뷰 요청 사항`) 규칙을 따른다.
- 양식에 없는 내용(자동 생성 표기 등)은 본문에 추가하지 않는다.

### 4. 승인 요청

- 아래 **승인 요청 멘트**로 초안을 요약해 사용자의 승인을 받는다.
- 사용자가 전문을 요청하면 초안 전체를 보여준다.
- 수정 요청 시 `3. 초안 작성`으로 돌아간다.

### 5. 등록

- 승인 후 `gh pr create`로 등록한다.
- 등록 결과(PR 번호, URL)를 보고한다. 이후 병합은 사용자가 직접 수행한다. (`WorkflowRules.md`의 `6. 병합, 브랜치 파기` 참조)

## 멘트 규격

> 아래 형식을 그대로 사용하며, 각 항목은 한 줄로 간결하게 적는다.

### 권유 멘트

```
📌 PR 등록 권유
- 브랜치 : [현재 브랜치] → [대상 브랜치]
- 커밋 : n개
- 관련 Issue : #번호 / 확인 필요
- 필요 정보 : 완료조건 검증 결과
등록할까요?
```

### 승인 요청 멘트

```
📝 PR 등록 승인 요청
- Title : [변경 유형] 기능명
- 브랜치 : [현재 브랜치] → [대상 브랜치]
- 관련 Issue : Closes #a / Refs #b / 없음
- 변경 파일 : n개 (생성 a / 수정 b / 삭제 c)
- 검증 결과 : 충족 x / 전체 y
- 남은 작업 : 있음 / 없음
전문이 필요하면 요청해주세요. 등록할까요?
```
