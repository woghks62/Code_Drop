# Github Issue 등록 스킬

> 이 스킬은 **절차와 멘트 규격만** 정의한다.
>
> 규칙의 내용은 이 문서에 적지 않고, 각 단계에서 지정한 원본 문서의 섹션을 읽고 따른다. (`CLAUDE.md`의 `규칙 문서 관리` - 단일출처 유지)

---

## 절차

### 1. 권유 판단

- `WorkflowRules.md`의 `1. Github Issue` 섹션을 읽고 이슈가 필요한 업무인지 판단한다.
- 사용자가 이슈 없이 `개발`, `버그수정` 업무를 시작한다고 언급했고 이슈가 필요하다고 판단되면, 아래 **권유 멘트**로 권유한다.
- 사용자가 직접 이슈 등록을 요청한 경우 이 단계를 생략한다.

### 2. 정보 수집

- `Github Issue Rule.md`의 `2. 배경 / 목적` 섹션을 읽고, 해당 섹션에 기재할 내용을 사용자에게 질문한다.
- 조건이 충족되지 않으면 이슈 작성을 거부한다.
- 그 외 섹션에 필요한 정보가 부족하면 함께 질문하고, 임의로 채우지 않는다.

### 3. 초안 작성

- `Issues Template.md`의 양식을 기반으로 작성한다.
- 각 섹션은 `Github Issue Rule.md`의 해당 섹션(`1. Title` ~ `6. 특이사항`) 규칙을 따른다.
- Label은 `Github Issue Rule.md`의 `7. 기타 - Label`에서 하나를 선택한다.

### 4. 승인 요청

- 아래 **승인 요청 멘트**로 초안을 요약해 사용자의 승인을 받는다.
- 사용자가 전문을 요청하면 초안 전체를 보여준다.
- 수정 요청 시 `3. 초안 작성`으로 돌아간다.

### 5. 등록

- 승인 후 `gh issue create`로 등록하고 Label을 할당한다.
    - 해당 Label이 저장소에 없으면 `gh label create`로 생성 후 할당한다.
- 등록 결과(이슈 번호, URL)를 보고한다. 이후 개발은 사용자가 직접 수행한다. (`WorkflowRules.md`의 `2. 개발` 참조)

## 멘트 규격

> 아래 형식을 그대로 사용하며, 각 항목은 한 줄로 간결하게 적는다.

### 권유 멘트

```
📌 이슈 등록 권유
- 업무 : [기능 단위 한 줄]
- 이유 : [이슈가 필요한 이유 한 줄]
- 필요 정보 : 배경 / 목적
등록할까요? (거절 시 이슈 없이 진행)
```

### 승인 요청 멘트

```
📝 이슈 등록 승인 요청
- Title : [Title]
- Label : [Label]
- 배경 / 목적 : [요약 1~2줄]
- 작업 파일 : n개 (생성 a / 수정 b / 삭제 c)
- 특이사항 : 있음(#번호) / 없음
전문이 필요하면 요청해주세요. 등록할까요?
```
