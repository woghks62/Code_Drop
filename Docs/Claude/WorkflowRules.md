# Workflow 규칙

> Claude가 업무 수행 시 지켜야 하는 업무 프로세스
>
> Claude는 Github Issue 작성, 시스템 기술 문서 작성, Github PR 작성, 개인 작업일지 작성만 담당한다.
> 소스코드 작성·수정, Git 명령(Commit, Push, 병합)은 사용자가 직접 수행한다.
>
> 해당 문서에 기재되지 않는 임무가 발생할 경우, 이 지침에 대한 개선을 사용자에게 권유한다.

---

## 0. 전체 흐름

- 각 단계의 수행 주체(Claude / 사용자)를 지킨다.
    ```mermaid
    flowchart TD
        Start[개발 / 버그수정] --> Issue["1. Github Issue (Claude)"]
        Issue --> Dev["2. 개발 (사용자)"]
        Dev --> Doc["3. 기술 문서 작성 (Claude)"]
        Doc --> Commit["4. Commit / Push (사용자)"]
        Commit --> PR["5. PR (Claude)"]
        PR --> Merge["6. 병합, 브랜치 파기 (사용자)"]
        Merge --> Close["7. Issue Close (Claude)"]

        Log["8. 작업일지 (Claude)<br/>하루 작업 종료 시 사용자 요청"]

        IssueNote["이슈가 필요하다고 판단하는 경우<br/>사용자에게 작성 권유"] -.-> Issue
        DocNote["사용자 요청 시에만 작성<br/>요청이 없으면 생략"] -.-> Doc
    ```

## 1. Github Issue

- 사용자가 `개발`, `버그수정` 업무를 시작한다고 언급하면, Issue 등록이 필요한지 판단해 작성을 권유한다.
    - 권유만 하며, 사용자가 거절하면 Issue 없이 진행한다.
    - 사용자가 Issue 생성을 명시적으로 금지한 경우 권유하지 않는다.
- 권유 및 작성/등록은 `github-issue` 스킬로 수행한다.

## 2. 개발

- **사용자가 직접 수행한다.** Claude는 소스코드를 작성·수정하지 않는다.

## 3. 기술 문서 작성

- 사용자가 요청하면, 사용자가 작성한 소스코드를 기반으로 시스템 기술 문서를 작성·수정한다.
- 작성 규칙은 `Docs\Documentation\Tech Doc Rule.md`, 양식은 `Docs\Template\Tech Doc Template.md`를 따른다.
- 요청이 없으면 이 단계를 생략한다.
- 아래 순서로 진행한다.
    1. **정보 수집 (메인 세션)** : 대상 문서 경로, 생성/수정 구분, 관련 소스 파일을 정리한다. 코드로 확인할 수 없는 정보(설계 결정의 이유, 씬·Prefab 설정값, Play 테스트 결과)는 사용자에게 질문한다.
        - 기존 문서를 수정하는 경우, 이 단계에서 사용자의 승인을 받는다.
    2. **작성 (`doc-writer`)** : 1에서 정리한 내용을 전달해 문서를 작성·수정한다.
    3. **검수 (`doc-reviewer`)** : 대상 문서 경로와 관련 소스 파일 목록을 전달해 문서와 코드를 대조한다.
    4. **사용자 검수 (메인 세션)** : 작성 결과와 검수 리포트를 사용자에게 보고하고 승인을 받는다.
        - 반려되거나 검수 판정이 `수정 필요`이면, 사용자에게 수정 여부를 확인한 뒤 2로 돌아간다.

## 4. Commit / Push

- **사용자가 직접 수행한다.** Claude는 Git 명령을 실행하지 않는다.
- 사용자의 Push 완료 언급을 받은 후 `5. PR`로 넘어간다.

## 5. PR

- Push가 완료되었다는 사용자의 언급을 받은 후 Claude가 PR을 작성한다.
- 권유 및 작성/등록은 `github-pr` 스킬로 수행한다.

## 6. 병합, 브랜치 파기

- **사용자가 직접 수행한다.** Claude는 병합 및 브랜치 삭제를 실행하지 않는다.
- 사용자의 병합 완료 언급을 받은 후 `7. Issue Close`로 넘어간다.

## 7. Issue Close

- 병합 완료 후 Claude가 관련 Issue를 Close 한다.
- Close 전, Issue의 `완료조건 (DoD)` 체크리스트가 모두 충족되었는지 사용자에게 확인한다.
    - 충족되지 않은 항목이 있으면 Close 하지 않고 사용자에게 보고한다.
- Issue 없이 진행한 업무는 이 단계를 생략한다.

## 8. 작업일지

- 사용자가 요청하면 금일 작업에 대한 개인 작업일지를 작성한다.
- 작성은 `work-log` 스킬로 수행한다.
