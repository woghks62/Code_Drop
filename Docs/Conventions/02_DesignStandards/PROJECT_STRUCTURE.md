# 프로젝트 구조 및 에셋 관리

## 03. 프로젝트 구조 및 에셋 관리

### 03-1. 기본 폴더 구조

- 프로젝트에서 직접 제작한 에셋과 스크립트는 `Assets/` 바로 아래의 종류별 폴더에서 관리한다.
- 기본적으로 `Core`, `Gameplay`, `UI`, `Data`, `Editor` 등 역할별 폴더 구조를 사용한다.
- 관련 스크립트가 많아져 관리가 어려워지는 경우에만 기능별 하위 폴더를 생성한다.
- 불필요한 폴더 세분화는 피한다.
- 외부에서 다운로드하거나 임포트한 에셋은 `Assets/Imports/` 폴더에 모아서 관리한다.
- `Assets/Imports/`는 기본적으로 `.gitignore`에 등록하여 GitHub에 업로드하지 않는다.
- 단, 팀 프로젝트에서 해당 에셋에 의존하는 경우 공유 방법을 먼저 확인한다.
- 외부 에셋을 수정하거나 다른 폴더로 이동할 때는 기존 참조와 라이선스를 확인한다.

#### 기본 폴더 구조

```text
Assets/
├── Scripts/
│   ├── Core/
│   ├── Gameplay/
│   │   ├── Player/
│   │   └── Enemy/
│   ├── UI/
│   ├── Data/
│   └── Editor/
├── Prefabs/
├── Scenes/
├── Materials/
├── Textures/
├── Animations/
├── Audio/
├── Fonts/
├── Settings/
└── Imports/
```
#### .gitignore 설정
/Assets/Imports/

### 03-2. 외부 에셋 및 패키지
- 서드파티 에셋은 프로젝트 자체 에셋과 구분하고 원본을 보존한다.
- 다운로드한 외부 에셋은 기본적으로 `Assets/Imports/`에서 관리하며, `.gitignore`에 등록하여 GitHub에 업로드하지 않는다.
- 벤더가 요구하는 폴더 구조가 있다면 이를 존중한다.
- 패키지 설치·업데이트·삭제, `Packages/manifest.json` 변경, 서드파티 원본 수정은 사전 승인을 받는다.
- 팀 프로젝트에서 외부 에셋에 의존하는 경우, 팀원이 해당 에셋을 사용할 수 있는지 확인하고 설치 방법을 공유한다.

### 03-3. Scene 및 Prefab 수정 범위
- 요청받은 기능 구현에 필요한 Scene 및 Prefab 수정은 허용한다.
- GameObject 생성, 컴포넌트 추가, Inspector 값 변경 등은 작업 범위 내에서 수행할 수 있다.
- 기존 GameObject나 컴포넌트 삭제, 대규모 계층 구조 변경은 사전 승인을 받는다.
- 다른 시스템에서 참조하는 오브젝트를 변경할 때는 영향을 먼저 확인한다.
- Unity 에셋의 GUID 및 참조 관계를 보존한다.
- 요청 범위를 벗어난 Scene 및 Prefab은 임의로 수정하지 않는다.
